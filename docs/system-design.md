# 系统设计

## 设计原则

1. **以终为始**：先明确学习成果（分享、面试、决策支持），再反推学习范围。
2. **输出倒逼输入**：每个模块必须产出笔记、讲解或测验题，不产出视为未完成。
3. **闭环自迭代**：检验结果回流到知识地图和复习计划，系统越用越准。
4. **可复用**：方法论与领域解耦，新领域复制目录模板即可启动。
5. **克制范围**：优先覆盖高频、高价值知识点，拒绝百科式收录。

## 五阶段闭环

### 1. 定向（Scope）

回答四个问题：为什么学、学到什么深度、什么时间投入、什么算学成。

产出：《领域立项简报》，包含目标场景、深度边界、时间预算、验收标准。

关键动作：
- 定义 2-3 个真实使用场景（例如「能向团队讲清 AI Agent 的架构取舍」）。
- 用知识分级（见下文）声明目标层级。
- 设定时间盒，例如「4 周，每周 5 小时」。

### 2. 收集（Collect）

扫描权威信息源，构建领域知识地图，并用优先级矩阵筛选。

产出：《知识地图》，包含领域分层结构、信息源清单、优先级标注。

信息源优先级：
1. 官方文档、经典教材、综述论文
2. 权威工程师/研究者的课程、博客、演讲
3. 高质量技术社区讨论
4. 二手解读文章（仅作补充，不作依据）

优先级矩阵：

| | 学习成本低 | 学习成本高 |
| --- | --- | --- |
| **重要性高** | P0 必学 | P1 计划学 |
| **重要性低** | P2 按需学 | P3 暂缓 |

### 3. 学习（Learn）

把知识地图拆成课程模块，每个模块独立可完成、可检验。

产出：《课程大纲》+ 每模块《费曼笔记》。

课程模块结构：
- 每个模块对应知识地图的一个分支或主题。
- 每个模块包含：核心概念、关键问题、学习材料、实践任务、预计时长。
- 模块完成标准：能用自己的话讲清，且通过该模块测验。

### 4. 检验（Test）

用三类方式交叉验证，避免「看懂了」的错觉。

| 方式 | 验证什么 | 形式 |
| --- | --- | --- |
| 分层测验 | 概念、原理、应用 | 客观题 + 场景题 |
| 费曼讲解 | 表达与理解深度 | 5-10 分钟口述或写作 |
| 输出物评审 | 真实场景可用性 | 分享大纲、面试答案 |

测验分层：
- L1 识记：是什么、有哪些。
- L2 理解：为什么、区别是什么。
- L3 应用：给定场景如何选型、如何排查。
- L4 讲授：如何向不同受众讲清。

### 5. 迭代（Iterate）

检验结果驱动两件事：生成复习计划、更新知识地图。

产出：《复习计划》+《领域复盘》。

迭代规则：
- 测验正确率低于 80% 的知识点进入复习队列。
- 复习采用间隔重复：1 天、3 天、7 天、14 天、30 天。
- 连续两次通过的知识点降频，连续两次失败的知识点回到学习阶段。
- 每轮领域复盘检查：目标是否达成、范围是否需要调整、模板是否需要改进。

## 知识分级体系

| 层级 | 定义 | 检验方式 | 典型投入 |
| --- | --- | --- | --- |
| L1 了解 | 能说出概念和适用范围 | 选择题、名词解释 | 低 |
| L2 理解 | 能解释原理和取舍 | 对比题、简答题 | 中 |
| L3 应用 | 能在场景中选型和排障 | 场景题、案例分析 | 高 |
| L4 讲授 | 能向他人讲清并回答追问 | 费曼讲解、分享 | 最高 |

建议：核心主题目标 L3-L4，外围主题目标 L1-L2。不必全领域 L4。

## 自迭代机制

系统通过三条反馈回路自我修正：

1. **知识回路**：检验暴露的盲区回流到知识地图，补充节点或材料。
2. **方法回路**：复盘发现流程问题（例如材料太杂、模块太大）时修订模板。
3. **目标回路**：使用场景变化时重新定向，允许放弃或降级部分目标。

## 度量指标

| 指标 | 定义 | 健康值 |
| --- | --- | --- |
| 模块完成率 | 已完成模块 / 计划模块 | >= 80% |
| 测验通过率 | 首次通过知识点 / 已测验知识点 | >= 70% |
| 复习留存率 | 复习时仍答对的知识点比例 | >= 80% |
| 输出物数量 | 分享大纲、面试答案、讲解记录 | 每领域 >= 3 |

指标不用于考核，用于发现系统问题：完成率低说明计划过重，通过率低说明材料或测验设计有问题。
